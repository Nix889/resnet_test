# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A ResNet-based pipeline that reads analog gauges from photos: given an image, it predicts the angle(s) of the needle(s), optionally locates the scale's min/max reference marks, and can convert that into an actual physical reading (e.g. "47 PSI"). This is a flat collection of CLI scripts (no package/app framework) sharing one module, `common.py`.

`DOCUMENTATION.md` is the authoritative design doc — problem analysis, every non-obvious decision with its rationale, and a dated development record. Read it before making architectural changes; update it (§ development record) when you make one.

## Commands

There is no test suite, linter, or build step. The only "check" step used in this repo is a syntax compile of every script (do this after any edit):

```
python -m py_compile common.py train.py test.py predict.py annotate.py split_dataset.py compare_pretrained.py augment.py
```

**Do not generate test/synthetic images to verify functionality** (no drawn gauges, no rendered overlays, no before/after comparison PNGs). Verification in this repo is limited to the syntax compile above, plus reading through the logic. The user checks actual functionality (angle/label math, overlays, training runs) manually themselves.

### Pipeline scripts, in the order they're normally run

```
python annotate.py [--needles 1|2]                        # click-to-label images/train/original -> labels.csv (always labels both ref marks)
python augment.py [--brightness] [--contrast]              # augmented copies (120x120) -> images/train/augmented
python split_dataset.py                                    # stratified, leakage-safe split -> images/train/dataset/{train,val,test}.csv
python train.py --arch resnet50 --epochs 30                # trains, writes runs/<arch>/<timestamp>/{best_model.pt,params.json,history.json,metrics.png}
python test.py --checkpoint runs/<dir>/best_model.pt        # evaluates on dataset/test.csv (--vis-dir for overlays)
python predict.py --checkpoint runs/<dir>/best_model.pt     # inference on images/predict/ (--vis-dir for overlays)
python compare_pretrained.py                                # trains pretrained vs. from-scratch back-to-back
```

Every script defaults to the fixed `images/` layout (see below) and to `resnet50`/pretrained/circular-angle regression; run with `--help` for the full flag set (loss function, image size, augmentation, stratification bins, etc.) rather than assuming — flags have shifted across this project's iterations.

## Architecture

### Fixed on-disk layout (`common.py` path constants)

```
images/
  train/
    original/    # raw labeled images + labels.csv -- source of truth, hand-annotated
    augmented/   # generated by augment.py
    dataset/     # generated by split_dataset.py (train.csv/val.csv/test.csv)
  predict/       # unlabeled images, exclusively for predict.py
```

`dataset/*.csv` filenames are prefixed `original/` or `augmented/` so a single `--img-dir images/train` resolves both sibling folders. `split_dataset.py` decides the split on **original images only** and appends augmented rows to the train split alone (keyed by `source_filename`) — this is deliberate leakage prevention, not an oversight; don't "simplify" it into splitting the combined pool.

### CSV schema drives everything — there are no needle-count/reference-mark flags on most scripts

Labels CSVs have `filename` plus `angle_1` (needle 1), optionally `angle_2` (needle 2), optionally `ref_angle_min`/`ref_angle_max` (scale reference marks — `annotate.py` now always labels both, but older CSVs without them still load). `common.py::get_angle_columns()`/`get_reference_columns()` auto-detect which are present from the header, and everything downstream (`GaugeAngleDataset.num_needles/.num_reference`, `build_model()`'s output width, `train.py`'s checkpoint contents) follows from that. Only `annotate.py` needs an explicit `--needles` flag, since it's the one place there's no CSV yet to infer from. To test a 1-needle vs. 2-needle model, label into separate CSVs and point scripts at whichever one — don't add a needle-count flag to `train.py`/`test.py`/`predict.py`, it would be redundant with the CSV and could get out of sync with it.

### Angle regression is circular (sin/cos), not raw degrees

`build_model()`'s output layer is `2 * (num_needles + num_reference)` — a `(sin, cos)` pair per angle, not a single raw-degree neuron. This makes 359° and 1° correctly close in output space instead of penalized as opposite. Core functions: `encode_angles()`/`decode_angles()`/`circular_abs_error_deg()` in `common.py`. Any new angle-producing or angle-consuming code should go through these, not raw degree arithmetic — the standard `%360` degree wraparound bugs (e.g. naive angle subtraction) are exactly what this encoding avoids.

### Augment.py is photometric + angle-preserving geometric, labels never change

`augment.py` applies brightness jitter, contrast jitter, slight blur, and small translate/scale. Translate and uniform scale *are* geometric transforms, but neither rotates nor mirrors the image, so the pivot→tip direction — and therefore the angle label — is unchanged; only rotation/flip would require relabeling, and neither is used. Every output image is resized to 120×120 px. Since no rotation/flip is applied, `train.py --augment` (in-memory, photometric-only) and `augment.py` (on-disk) can be combined freely.

### Reference marks and physical readings are angles, not pixel coordinates

`ref_angle_min`/`ref_angle_max` are regressed exactly like a needle angle. In `annotate.py`, every point in an image — each needle and both reference marks — measures its angle from one shared pivot: the gauge's center, clicked once per image (for now; independent per-point pivots existed before and could return if multi-dial gauges show up). `compute_reading()` converts a needle angle + the two reference angles into a physical value; it auto-selects which of the two candidate arcs between min and max is the valid scale using the needle's own position (never assume a fixed sweep direction — camera framing in this project varies shot-to-shot, so there's no reliable global convention to hardcode). The physical values at those reference marks (`--value-min`/`--value-max`) are supplied externally, never predicted — reading printed numbers off a dial is an OCR problem, out of scope for this regression head.

### Checkpoints are self-describing

`train.py` saves `arch`, `pretrained`, `img_size`, `num_needles`, `num_reference` into the checkpoint dict alongside weights. `test.py`/`predict.py` rebuild the exact matching model/preprocessing from the checkpoint alone — never require these as re-specified flags at test/inference time, and never assume a checkpoint predates `num_reference` without using `.get("num_reference", 0)` for backward compatibility.
